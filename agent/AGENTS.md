# Global instructions

- Every code change of any size uses fresh native herdr worktree → bounded Delivery Lead → `worker` and independent fresh review. Any full session can own this flow. Only trivial configuration may bypass it and use a fixer on `cloudflare-ai-gateway/claude-opus-5-5`, followed by independent review. Adopting an already reviewed and tested immutable dependency revision, with its aligned prose, is trivial configuration when it needs no consuming-repo code change, migration or unresolved compatibility work: route it through fixer/writer and independent review, not a new Delivery Lead delivery. The consuming repo's required checks still run. Unqualified dependency upgrades stay in the code flow. Every native leaf launch uses the qualified model, explicit effort and complete contract in `configs/session-roles.json` and `configs/delegation.md`.
- Existing managed participants execute their assigned roles without recursive wrapping. A native leaf never delegates, launches panes, triggers review or adjudicates its own implementation. A leaf receiving code outside the managed flow requests routing from its parent; it never creates a second scope. Delegated non-code authoring, recon and diagnosis use the writer, scout, oracle or debugger prompt contracts in `configs/delegation.md`.
- Delegation or runtime failure: preserve the exact error and run/command identities, report to the launching parent and stop. Never implement or perform independent review inline. Do not retry uncertain launches. Standalone pi-intercom requires Pi >=1.5.0; never load both Intercom extensions. Restart the process to change SDK versions. `/reload` does not upgrade the host.
- Network loss and laptop sleep are expected. A model transport failure, such as `Request timed out.` or `read ETIMEDOUT`, pauses the work. It never permanently rules out contacting that model later, even after earlier timeouts or exhausted Pi retries. Not every runtime error is a network fault; judge it from the exact error. Preserve the error and native/command identities and report the interruption. There is no automatic retry loop. At a later recovery, inspect the recorded transcript, native identity and process state to learn what already ran. A bounded route probe, `pi --print --no-session --model <id> "Reply ok"`, may show the model is reachable now. A failed probe pauses until a later recovery, never rapid repeated launches. Prefer continuing the same owned session: once it is settled and `herdr agent get <recorded-pane>` still binds the recorded UUID, prompt it with its original brief and what already ran. Launch a fresh replacement with the same brief only after verifying the original actor and its commands settled. Uncertain launch, task delivery or command outcomes, trust/auth prompts, live commands and unknown ownership stay stop conditions. Never replay an uncertain mutation or duplicate an actor because a model call failed. Independent review, required gates, authority and escalation are unchanged.

## Skepticism discipline (any claim that the world changed)

Check assumptions → make the change → verify the result.

1. BEFORE — name the load-bearing assumption and test it: reproduce the bug before fixing it, validate the key/path/flag against the parser before editing the config, prove a file's inertness by checking what actually reads it there. Strongest source wins: parser over docs, behavior over docs, live state over memory.
2. AFTER — verify the end state through a different channel than the one that made the change: exercise the user's actual goal for real (click the link, boot a fresh process, read the file back). The apply-command's own success output is not evidence. If the repo encodes a check (test suite, validate script), run it on the FINAL state — "the edit applied" is never the check.
3. One passing check does not disprove an intermittent fault, and one sample per side does not show equivalence or cause — report differences as observed, cause undetermined. Before removing a guard, reproduce the failure condition it guards against (dead agent socket, expired token) and show the system survives without it.
4. If either check isn't possible, say "untested" — never dress it as success.
5. A failure the user has hit repeatedly is a premise question, not a patch: name the assumption the mechanism encodes, test it against who actually writes and reads each thing it touches, and offer the shapes that replace it before any incremental fix. A rule that blocks the replacement gets `git log -S` first — a rule born in the same commit as the mechanism is part of the mechanism, not a constraint on replacing it.

- Write only what the reader needs to act at the point they are reading. Before a choice (catalog entries, --list, descriptions, titles, todo items, report lines, TUI replies): the deciding facts, one clause or one screen. After a choice (bodies, header comments, review comments, reports): the acting facts — step, fact, evidence pointer — never the reasoning history or what was considered and rejected. Test: delete a sentence — if the reader can still act, it stays deleted. Keep verbatim what must be verbatim (Owner outcome blocks) and what loses data if cut (recovery steps, the fix in an error). Cutting words keeps modality: can/may never becomes must, and a scoped rule never widens.
- Reply = answer + evidence pointer. Go longer only if asked, the premise is wrong (one sentence), or silence would break the next action. Everything else waits for a follow-up. When the user must judge candidates, hand them one file or one screen with the candidates side by side — never a directory or a list of paths.

## Credential protection

- Never read or copy `auth.json` or `mcp-auth.json` contents through bash/codemode.
- Never copy `auth.json` or `mcp-auth.json` to `/tmp` or elsewhere.
- Never put credentials in config test fixtures.
- Cloak masks configured matches in `read`, `bash` and `grep` output, including inner codemode calls. Path-based masking requires a matching file path in the call.
